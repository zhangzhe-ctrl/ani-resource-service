# NET-05A：CR 持续观察与执行扩展方案

> 历史方案：网络状态消费、准入与释放条款已由[2026-11-04 实施方案](network-management-simplification.md)及[规格 v3](../specs/cr-observation.md)替代。历史执行事实继续按原记录阅读。

日期：2026-09-10。用户要求将持续观察改造放在 NET-06 前，并将配额接入延后到 Core 重构之后。本文件编排独立实现与验收工作包，行为只以[持续观察规格](../specs/cr-observation.md)及其引用为准，不复制状态机或维护另一份进度表。

## 1. 位置与输入

```text
NET-01～04 → NET-05 普通容器真实验收 → NET-05A 持续观察改造 → NET-06 VM 验收
```

保留 NET-05、NET-06 的编号和含义。NET-05A 使用 NET-05 已验收的 Network/ANI commit、镜像、kc API/镜像、环境与普通容器行为作为对照，开始实施时重新冻结其精确身份；当前选型代码仅为设计输入，不能取代届时基线。NET-06 必须消费 NET-05A 通过后的实现及证据。

本轮交付方案与编排，不启动代码实施、迁移、环境操作、提交或发布。后续启动本包时在独立 `codex/` worktree 工作；优先 ubuntu 执行编译、完整测试、真实 PG 和构建，遵循[远程执行约定](../remote-execution.md)。远端不可用的回退需记录原因、主机、源码身份和实际命令。

## 2. 交付范围

交付共享 VPC/Subnet 观察、Pod/VNic/VNicIP/EIP 关系索引、持久通知合并、共享真实校验、时效与恢复、公平有界 worker，以及相应迁移/测试/运行说明。在既有独立 Network 领域路径上实现，不增加另一套产品状态写入者。

| 计划路径 | 用途 |
|---|---|
| `internal/biz/network/worker.go`、`attachment_worker.go` 及相关端口/测试 | 统一领域执行、证据输入、并发与恢复规则 |
| `internal/data/network/kc*.go` 及新增观察/索引 adapter、相应测试 | 标准 informer、直接核验、共享关系事实、Provider 归属 |
| `internal/data/network/queries/`、`internal/data/network/sqlcgen/` 和既有迁移目录 | 持久代次、调度、公平领取与租户约束；启动时列明具体迁移路径 |
| `internal/server/worker.go`、`cmd/ani-resource-service/`、实际配置入口 | 观察与执行生命周期、运行参数、健康及遥测 |
| 现有测试/构建入口、`docs/runtime*.md`、本包记录 | 可复现验证与运维说明；具体新增脚本在启动时固定 |

API 字段、公开状态、Gateway、ANI 实例实现及 kc controller 均不是默认变更范围。需要跨仓修改或改变公开契约时，先记录触发原因和具体差异再单独限定工作；不借本包扩展兄弟服务、VM 或旧 Core 控制权交接。

配额不作为本包依赖或退出条件：不实现 Reserve/Confirm/Release 配额协议、账本/预留表、结算 outbox/dispatcher、Watch 对象计数配额，也不预建临时接口。既有 Network Attachment 占用和删除保护照常回归。

## 3. 实施步骤

这些步骤属于同一工作包，局部通过不表示 NET-05A 完成。

| 步骤 | 实施内容 | 阶段产物 |
|---|---|---|
| A. 冻结输入与测量基线 | 固定 NET-05 来源、权限/范围、公开 version 实际行为、测试主机及容量数据集；测量当前 GET/LIST、PG 与排队成本 | 来源清单、调用轨迹、候选参数预算和验收用例，不以估算代替测量 |
| B. 先闭合持久调度 | 新增通知代次及迁移，改造 Claim/Finish 竞争、公平领取和有界并发；在受控通知下保持原 Provider 路径 | 真实 PG 迁移/升级、租户负向、丢唤醒与旧执行者故障证据 |
| C. 接入 VPC/Subnet 共享观察 | informer 生命周期、范围/身份映射、status-only 提示、队列桥接、启动扫描及连接错误恢复 | 受控 List/Watch 故障与状态传播；尚无 CR 的工作独立恢复 |
| D. 替换重复关系扫描 | 共享 Pod/VNic/VNicIP/EIP 索引和完整范围校验，保留 owner 封闭查询及关键直接核验 | Attachment/删除全链路竞争、孤儿关系、错误 UID 和只读权限证据 |
| E. 完成时效与运行治理 | 来源代次/审计视图同步、跨副本缓存与通知覆盖证明、证据应用、校验预算、背压、公平性与遥测；比较规模与冷启动成本 | V-16～18 及受影响 V-01～11 证据；明确部署容量边界 |
| F. 新版本真实复验 | 构建精确新版本，在获准的隔离环境验证真实 Watch，并复验普通容器闭环 | V-19、新版本镜像/源码与完整清理证据，形成 NET-06 输入 |

先接 VPC/Subnet、仍保留每 Attachment 全集群扫描，只能算中间状态。修改代码的各阶段运行适用的生成检查和 `make verify`；真实 PG、独立进程、受控 Watch、容量及真实 kc 证据分别取得，不把普通单元测试包装成上述行为通过。

## 4. 验证与退出

验收断言唯一来源为规格 V-16～19；原 V-01～15 的编号和历史证据不重排。受影响的旧门禁需按新架构调整测试隔离后回归，尤其 V-09 必须区分查询副作用与合法后台 List/Watch。

| 证据层 | 本包要求 |
|---|---|
| 源码与生成 | 固定生成流程、`make verify`、公开契约/版本兼容、无新增跨层依赖 |
| 真实 PostgreSQL | 空库与现有 NET-02/03 schema 升级、通知交错、多副本、租户边界、恢复、受限运行角色 |
| 受控 Provider/独立进程 | Watch 协议错误与断线、队列丢失、旧快照、应用暂停、未知请求、owner 两端恢复 |
| 容量对照 | 固定数据集的正常/倍增负载、变化风暴、冷启动及重连；分列延迟、请求/字节、PG 写入与内存，指出瓶颈 |
| 真实 kc 与普通容器 | 本包精确镜像的 Watch 权限/重连/状态；产品入口、连通隔离、引用保护、释放与清理 |

NET-05A 完成需要适用生成/功能门禁与 V-16～19 通过，并在事先固定的容量与时效预算内形成可使用的配置。达不到性能目标时如实记录并修复或明确修订目标，不能只保留好看的样本。集群权限/Provider 缺口只阻断对应层，不阻止独立本地设计与受控验证推进，但 `not_verified` 不能作为完成。

本包记录放在 `docs/execution/records/NET-05A/`（实施时按需创建），包含源身份、环境、实际命令/退出码、断言结果、容量数据与限制。当前状态只更新[执行状态](../execution/status.md)。NET-05 的旧镜像和测试记录仅作基线，不能直接复用为新观察实现的通过证据。

## 5. 交付与恢复安排

Schema 采用新增迁移并保留已执行文件。记录旧/新程序对新增列和通知调度的兼容性；不能假设旧 worker 知道如何保留新通知，也不能未经验证混跑两个版本。升级演练应停止旧执行者并核对在途请求，再启动新执行者恢复持久工作。

若需要回退，先验证目标旧版本、schema 兼容、停止新执行者和持久工作可恢复，再执行已限定的回退；不得删除业务意图、重置 UID/pending_action 或清空租约表来掩盖未知结果。这里只设计隔离验证环境的升级/恢复，不承诺或执行生产回滚。

向 NET-06 交付精确版本、通过的观察与普通容器证据、Provider 观察范围/权限及容量配置。向兄弟仓库交付可引用的职责规则和故障矩阵；它们可自行选择 controller-runtime，本包不修改其实现。

## 6. Core 重构后的配额接入

待 Core 重构完成且治理 owner 提供已接受的配额权威、版本化契约与恢复语义后，再独立编排配额工作包。届时明确额度范围、预留与提交资格、未知请求处理、幂等/有序结算、存量账实核对及启用策略；当前不预先固定这些接口。

本包只保证产品身份、持久意图、状态转换与真实清理证据仍可作为未来协议输入。配额延期不影响 NET-05A 和 NET-06 推进，也不表示当前已经具备 VPC 配额保护；选型记录里的配额讨论保留为候选设计输入。

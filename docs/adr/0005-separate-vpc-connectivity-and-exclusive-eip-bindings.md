# 基础内网与公网出口分别占用，EIP 按目标独占

用户已确认：一个 EIP 同时只能关联一个目标，不能同时用于 VPC SNAT 和 LB；既有“每 VPC 一个 SNAT”限制改为按内网/公网用途分别限制，并补齐基础内网资源的自动创建、恢复、删除和就绪判断。内网连接承担 VPC 的系统依赖，不因租户绑定、停用或解绑公网出口而移除。

因此，基础内网连接由 Network 随 VPC 管理，租户按需管理公网出站和 LB 公网入口。数据库层统一预留 EIP 使用目标，避免 SNAT 与 LB 两张独立占用表都接受同一个地址；VPC 的内网与公网 SNAT 分别限制数量。代价是需要演进旧唯一性约束、EIP 查询、删除编排和存量补齐，而不能只在 VPC 创建末尾附加一次 Kubernetes 调用。

本 ADR 只记录上述已确认规则。具体 API、表结构、首批 LB 协议范围和任务划分属于[统一方案](../specs/vpc-connectivity-lb.md)的工程提案；没有因此授权代码实现、数据库迁移、存量回填或部署。

2026-10-30 用户更新：公网绑定和再启用不依赖基础内网 EIP/SNAT；基础缺失或故障不阻止已具有自身 Ready 证据的 VPC 使用公网。VPC 自身身份、代次、时效、未决写与删除栅栏，以及公网池与 EIP 检查保留；LB 的基础准入不在本次调整范围。准确合同见统一方案第 5 节。

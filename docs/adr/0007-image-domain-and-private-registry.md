# Image MVP 决策输入（待按下一可用 ADR 编号落库）

## 用户明确约束

同仓同 module 同进程，Image 领域自治；租户隔离、平台共享、多用途标签、自定义 Push；Harbor 不开放管理 Web；无 RLS；本地仅编辑/Git/转运，重任务必须 Fedora；缩小到登记与一种工作负载使用闭环；不以完整镜像中心替代 MVP。

## 本方案工程决定

1. 登记固定 Digest，不同步完整 Harbor 目录。取消登记不删除底层镜像。
2. `platform` 和 `t-<slug>` 都是 Private；授权租户跨指定两 Project 只读。公共目录与匿名仓库不是同义词。
3. `image` 独立 PG schema/owner/runtime role、sqlc 输出和迁移版本；可复用同一 PG 实例，不复用 Network 表或迁移序列。
4. 租户一份长期受控保存的拉取身份，发布身份按需签发；凭证重置使用新一代 Robot，不建立逐用户凭证产品。
5. 少量 `commands` 行只用于同步请求的幂等和外部副作用恢复，不做 worker、队列、补偿平台、通用状态机。
6. 平台维护复用同一二进制的受控管理命令；不把平台写接口注册到租户 listener，不用空 tenant 表示平台管理员。
7. 普通镜像 API 走现有 Governance mTLS；拉取材料仅窄内部端口/严格内部 listener；Image 不创建 Pod/Namespace，不读取 Network SQL。
8. 精确按实源绑定普通容器和前端接入点；缺失时报告局部阻塞，不复制旧 ANI，不扩写 Compute、不替换成 KServe 项目。
9. 不为本任务改造已有账号体系、配额、GPU 调度、安全扫描与审计中心；现有日志保留必要身份和原因，但不记录 Secret。

## 明确代价

登记后同 Tag 更新不自动更新目录；只看已登记内容；共享发布身份无法逐人归因；Harbor 被外部删除的制品只能在解析/运行时发现；禁止未经检查的自动 GC；镜像用途是声明而不是运行认证；无 RLS 时应用角色仍能访问获授权的多租户行，隔离靠查询/约束/测试而非行级数据库策略。

本轮不解决企业高可用、跨集群 Secret 自动轮换、长生命周期密钥平台等问题。运行凭证到期前有受控更换手册；不能隐式依赖 Harbor 默认有效期或把有限期凭证当永久凭证。
